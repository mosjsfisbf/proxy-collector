# راهنمای دیپلوی نسخهٔ ریلوی — proxy-collector

## فایل‌های این پوشه
- `index.js` — کل سرویس (سرور اکسپرس، جمع‌آوری، پینگ موازی، پنل ادمین)
- `package.json` — نود ۲۰ به بالا، فقط وابستگی اکسپرس
- `railway.toml` — تنظیم ساخت و استارت
- `data/` — وقتی سرویس روشن شود، فایل `current.json` لیست پروکسی‌ها اینجا ذخیره می‌شود (**باید ولیوم وصل شود**)

## گام‌های دیپلوی در ریلوی
۱) یک پروژهٔ جدید بسازید و این پوشه را به عنوان سورس متصل کنید (گیت‌هاب یا آپلود).
۲) در تنظیمات سرویس، یک **Volume** بسازید و روی مسیر `/app/data` ماونت کنید. (اگر مسیر دیگری گذاشتید، متغیر محیطی `DATA_DIR` را همان مسیر قرار دهید.)
۳) متغیرهای محیطی را بگذارید:
   - `PANEL_PASSWORD=monsmain2026`
   - `MAX_PROXIES=25` (اختیاری، پیش‌فرض ۲۵ است)
۴) دیپلوی کنید. پورت از متغیر `PORT` که ریلوی خودش می‌دهد خوانده می‌شود — کاری لازم نیست.
۵) روی سرویس یک دامنهٔ عمومی فعال کنید (Settings → Networking → Generate Domain). آدرس جدید (مثلاً `https://xxx.up.railway.app`) را در موتور گو جایگزین آدرس کلودفلر کنید.

## بررسی پس از دیپلوی
- `GET /list` باید یک آرایهٔ جی‌سان از پروکسی‌ها برگرداند (عمومی).
- `GET /` یا `/admin` پنل را نشان می‌دهد؛ ورود با رمز بالا. ورود با `?key=` هم هنوز کار می‌کند (طبق دستور فرمانده).
- بعد از اولین چرخهٔ تازه‌سازی (بلافاصله یا حداکثر ۱۵ دقیقه) لیست پر می‌شود.

## نکته مهم
بدون ولیوم، فایلِ لیست با هر ری‌استارت پاک می‌شود — ولی سرویس همچنان کار می‌کند چون حافظهٔ درون‌حافظه‌ای هم دارد و هر چرخه دوباره لیست را بازسازی می‌کند. ولیوم فقط برای بقای سریع لیست پس از ری‌استارت است.
